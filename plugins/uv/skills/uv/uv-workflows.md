# uv Core Workflows

## Workflow 1: Starting a New Project

### Setup
```bash
uv init my-project
cd my-project
uv python pin 3.12
```

### Add dependencies
```bash
uv add requests
uv add "fastapi>=0.100.0"
uv add --dev pytest pytest-cov
```

### Run your code
```bash
uv run python main.py
uv run pytest
```

### What happens
- `uv init` creates `pyproject.toml`, `.python-version`, `.gitignore`
- `uv python pin` sets Python version in `.python-version`
- `uv add` updates `pyproject.toml` and creates `uv.lock`
- `uv run` creates `.venv` and runs commands inside it

### Commit to version control
```bash
git add pyproject.toml uv.lock .python-version
git commit -m "Initialize project with uv"
```

## Workflow 2: Adding & Updating Dependencies

### Add single dependency
```bash
uv add flask
uv run python -c "import flask; print(flask.__version__)"
```

### Add with version constraints
```bash
uv add "numpy>=1.20.0,<2.0.0"
uv add "django>=4.0"  # >= constraint only
```

### Add development-only dependencies
```bash
uv add --dev black ruff pytest
```

### Add optional dependency group
```bash
uv add --optional docs sphinx sphinx-rtd-theme
```

Then in `pyproject.toml`, users can install with:
```bash
uv sync --all-extras  # Install everything including optional groups
uv sync --extra docs  # Install only the docs group
```

### Update specific package
```bash
uv lock --upgrade-package requests
uv sync
```

### Remove dependency
```bash
uv remove requests
uv remove --dev pytest
```

## Workflow 3: Managing Virtual Environments

### Create a new venv (automatic)
Most `uv` commands auto-create `.venv`:
```bash
uv sync  # Creates .venv if it doesn't exist
```

### Create manually at custom location
```bash
uv venv /path/to/my/venv
source /path/to/my/venv/bin/activate  # Then use normally
```

### Run without activating (recommended)
```bash
uv run python script.py
uv run pytest
uv run flask --app app run
```

### Activate for interactive use (still works)
```bash
source .venv/bin/activate  # or .venv\Scripts\activate on Windows
python app.py
deactivate
```

### Create venv with specific Python
```bash
uv python install 3.11
uv venv --python 3.11 /path/to/venv311
```

## Workflow 4: Python Version Management

### Install Python versions
```bash
uv python install 3.12
uv python install 3.11 3.12 3.13  # Multiple
uv python list
```

### Pin project to Python version
```bash
# In project root:
uv python pin 3.12

# Creates .python-version file
cat .python-version  # 3.12
```

### Run with different Python
```bash
# One-off:
uv run --python 3.11 python script.py

# Project-wide:
uv python pin 3.11
uv sync
uv run python script.py  # Uses 3.11
```

### Test across versions
```bash
uv python install 3.10 3.11 3.12
for v in 3.10 3.11 3.12; do
  uv run --python $v pytest
done
```

## Workflow 5: Working with Lockfiles

### Understand the lockfile
- `uv.lock`: Records exact versions and hashes for reproducibility
- Auto-generated by `uv add`, `uv remove`, `uv lock`
- **Always commit to version control**

### Create/update lockfile
```bash
uv lock  # Creates or updates uv.lock based on pyproject.toml
```

### Upgrade dependencies
```bash
# Upgrade all:
uv lock --upgrade
uv sync

# Upgrade specific:
uv lock --upgrade-package fastapi
uv sync
```

### Install exact locked versions (CI)
```bash
# In CI, use --frozen to install exact versions:
uv sync --frozen

# Fails if uv.lock is out of date with pyproject.toml
uv lock --check
```

### Export for compatibility
```bash
# Generate requirements.txt from lockfile:
uv export --format requirements-txt > requirements.txt

# With hashes for security:
uv export --format requirements-txt --hash > requirements.txt
```

## Workflow 6: Running Tools (No Installation)

### Run tool temporarily with `uvx`
```bash
# Run ruff without installing it:
uvx ruff check .

# Run black without installing:
uvx black --line-length 100 src/

# Run legacy tools:
uvx poetry export -f requirements.txt
```

### vs `uv add` (permanent install)
```bash
# For tools you use in CI/CD or scripts:
uv add --dev ruff pytest black

# For one-off tools or testing:
uvx tool-name
```

## Workflow 7: Monorepo/Workspace Setup

### Directory structure
```
monorepo/
├── pyproject.toml          # Root workspace config
├── uv.lock                 # Single lockfile for all
├── packages/
│   ├── api/
│   │   └── pyproject.toml  # API package
│   └── cli/
│       └── pyproject.toml  # CLI package
└── .python-version
```

### Root `pyproject.toml`
```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.uv.workspace]
members = ["packages/*"]

[project]
dependencies = ["shared-dep"]  # Optional root dependencies
```

### Commands
```bash
# Install all workspace packages:
uv sync

# Install only for one package:
cd packages/api
uv sync

# Add dependency to one package:
cd packages/api
uv add requests  # Updates packages/api/pyproject.toml

# Add one package as dependency of another:
cd packages/cli
uv add --path ../api  # Adds api as editable dependency
```

## Workflow 8: CI/CD Integration

### GitHub Actions
```yaml
- uses: astral-sh/setup-uv@v2
  with:
    enable-cache: true
- run: uv sync --all-extras --dev
- run: uv run pytest
- run: uv run ruff check .
```

### Docker
```dockerfile
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev
COPY . .
CMD ["uv", "run", "python", "app.py"]
```

### Pre-commit
```yaml
- repo: local
  hooks:
    - id: uv-lock
      name: uv lock
      entry: uv lock
      language: system
      pass_filenames: false
```

## Workflow 9: Dependency Troubleshooting

### Check what's installed
```bash
uv tree
uv tree --outdated
uv pip list
```

### Clear cache if stuck
```bash
uv cache clean
uv sync --refresh
```

### Test installation in clean venv
```bash
rm -rf .venv
uv sync --frozen
```

### Export and inspect
```bash
uv export --format requirements-txt
cat requirements.txt  # See what actually resolves
```
